# Stripe Webhooks Reference

Server-side event handling. Webhooks are required for subscriptions, delayed payment methods, and any fulfillment side effect. Source: https://docs.stripe.com/webhooks (verified 2026-09-26).

## Register an endpoint

- Public HTTPS URL (TLS 1.2/1.3), up to 16 webhook endpoints per account. Register in Workbench → Webhooks or via the v2 Event Destinations API.
- Each endpoint has its own `whsec_` signing secret, different for sandbox/test and live. Store it like an API key (secrets vault, never in code).
- Local dev: `stripe listen --forward-to localhost:3000/webhook` prints a temporary `whsec_` secret.

```javascript
const dest = await stripe.v2.core.eventDestinations.create({
  name: 'orders',
  type: 'webhook_endpoint',
  events_from: ['@self'],
  event_payload: 'snapshot',          // or 'thin' (needs a separate endpoint)
  enabled_events: ['checkout.session.completed', 'checkout.session.async_payment_succeeded',
                   'checkout.session.async_payment_failed'],
  webhook_endpoint: { url: 'https://example.com/webhook' },
  include: ['webhook_endpoint.signing_secret'],
});
```

## Verify the signature (snapshot events)

Verification needs the **raw request body** exactly as received, the `Stripe-Signature` header, and the endpoint secret. Any JSON parsing or re-serialization before verification breaks it.

```javascript
import express from 'express';
import Stripe from 'stripe';

const stripe = new Stripe(process.env.STRIPE_SECRET_KEY);
const endpointSecret = process.env.STRIPE_WEBHOOK_SECRET;
const app = express();

// Route-level raw body; register before any global express.json()
app.post('/webhook', express.raw({ type: 'application/json' }), async (req, res) => {
  let event;
  try {
    event = stripe.webhooks.constructEvent(req.body, req.headers['stripe-signature'], endpointSecret);
  } catch (err) {
    return res.status(400).send(`Webhook Error: ${err.message}`); // StripeSignatureVerificationError
  }

  if (!(await claimEvent('stripe', event.id))) return res.sendStatus(200); // atomic claim on a unique (provider, event_id) index; a retry must be able to reclaim a failed or stale claim, see processWebhookIdempotently
  await enqueue(event);            // worker handles it, then records event.id as processed
  res.sendStatus(200);             // ack fast with 2xx
});
```

- Fetch API handlers (for example Next.js route handlers, Workers): read `await request.text()` and pass that string. Runtimes with only async Web Crypto need `await stripe.webhooks.constructEventAsync(...)`.
- Rails/Django: exempt the webhook route from CSRF protection.
- Other SDKs expose the same helper (Python `client.construct_event`, Go `sc.ConstructEvent` on the client instance, and so on). Manual verification: HMAC-SHA256 of `{t}.{raw_body}` with the secret, compared against each `v1=` signature in the header (constant-time compare).

## Replay tolerance

The header carries a signed timestamp `t=`. Libraries reject events older than a default tolerance of **5 minutes (300 s)**; the optional last argument changes it. Never use `0`, which disables the recency check. Keep server clocks synced (NTP). Retries get a fresh timestamp and signature.

## Idempotency, ordering, retries

- **Duplicates happen.** Record processed `event.id`s (unique constraint) and skip repeats. Some actions produce two distinct Event objects; dedupe those by `data.object.id` + `event.type`.
- **No ordering guarantee.** Don't rely on arrival order or `created` (second resolution). Make handlers state-based: retrieve the latest object from the API when order matters.
- **Snapshot data may be stale.** `event.data.object` is the object as of the event; re-fetch before irreversible actions.
- **Retries:** live mode retries with exponential backoff for up to 3 days; sandboxes retry 3 times over a few hours. Manual resend: `stripe events resend evt_xxx --webhook-endpoint=we_xxx` (within 30 days).
- Return `2xx` quickly and process through a queue; slow handlers cause timeouts and retries.
- Ignore unknown event types gracefully (return `2xx`).

## Checkout fulfillment

Fulfill from `checkout.session.completed` **and** `checkout.session.async_payment_succeeded`, only when `session.payment_status !== 'unpaid'`. Handle `checkout.session.async_payment_failed`. Subscriptions: `customer.subscription.created/updated/deleted`, `invoice.paid`, `invoice.payment_failed`. The success page never proves payment.

## Thin events (v2)

Thin events carry only IDs and are **unversioned**, so API upgrades don't change their payloads. They are generated by API v2 resources (v1 resources: private preview) and need a separate endpoint with `event_payload: 'thin'`.

```javascript
const notification = stripe.parseEventNotification(req.body, sig, thinSecret);
const obj = await notification.fetchRelatedObject(); // latest object
const full = await notification.fetchEvent();        // full v2 event when needed
```

Local: `stripe listen --forward-thin-to localhost:3000/webhook --thin-events "*"`.

## Hardening

- Roll signing secrets periodically or on suspicion (Workbench → Roll secret; old secret can stay valid up to 24 h, and Stripe signs with each active secret meanwhile).
- Optionally allowlist [Stripe webhook IPs](https://docs.stripe.com/ips.md) in addition to signatures.
- Don't log full payloads containing personal data; log `event.id` and `type`.
