# MCP protocol baseline: 2026-07-28

Current spec revision: **2026-07-28** (final, released 2026-07-28). Previous revisions:
2025-11-25 and 2025-06-18. Verify against the live spec before relying on this page for a
later date: https://modelcontextprotocol.io/specification/versioning

v2 SDKs (TypeScript `@modelcontextprotocol/server` 2.x, Python `mcp` 2.x, standalone
`fastmcp` 4.x) serve **both** protocol eras from one server. Build new servers on v2 and
let the SDK answer 2025-era clients; do not hand-roll the wire format.

## What changed in 2026-07-28 (server impact)

| Change | What it means for a server |
|---|---|
| Stateless core: no `initialize` handshake, no `Mcp-Session-Id` | Every request carries protocol version and client capabilities in `_meta`. Do not keep per-connection state; the SDK builds a server per request over HTTP. |
| `server/discover` is required | SDK implements it from your registrations. |
| Tool/resource/prompt lists must not vary per connection | They may vary by the authenticated principal, never by hidden session state. |
| State across calls uses explicit handles | Mint an opaque, random, expiring handle bound to the verified user and pass it as a tool argument. A handle is never authentication. |
| Multi round-trip requests (MRTR) replace server-initiated `elicitation/create`, `sampling/createMessage`, `roots/list` | Return an `input_required` result; the client retries the same call with `inputResponses`. See the language references for `inputRequired` / `Resolve`. |
| `subscriptions/listen` replaces the HTTP GET stream and `resources/subscribe` | Use SDK notify helpers; clients opt in per list type. |
| `ping` and `logging/setLevel` removed | Log level arrives per request in `_meta`. Do not emit `notifications/message` unless the request asked for logs. Log to stderr/OpenTelemetry instead. |
| SSE resumability (`Last-Event-ID`) removed | A dropped stream means the client re-issues the request; make mutating tools safe to re-issue (idempotency keys or check-then-act) and set `idempotentHint` truthfully. |
| List/read results carry `ttlMs` + `cacheScope` | SDK defaults exist; set cache hints when data is user-specific (`private`) or stable. |
| Resource-not-found is `-32602` (was `-32002`) | Use the SDK `ResourceNotFoundError`. |
| `inputSchema`/`outputSchema` accept any JSON Schema 2020-12 keyword; `structuredContent` may be any JSON value | `inputSchema` must still be an object schema. |
| Tasks moved out of core into extension `io.modelcontextprotocol/tasks` | Opt-in only. Python `mcp` 2.2 has no Tasks extension; FastMCP 4 uses `fastmcp-tasks`. |

### Streamable HTTP details

- One POST endpoint (conventionally `/mcp`). Each request returns JSON or a request-scoped
  SSE stream; closing the stream cancels the request.
- Clients send `MCP-Protocol-Version`, `Mcp-Method`, and `Mcp-Name` (for `tools/call`,
  `resources/read`, `prompts/get`). A mismatch with the body is `400` / `-32020`.
- A 2026-only server answers GET/DELETE with `405`. Send `X-Accel-Buffering: no` on SSE
  behind proxies.
- Optional `x-mcp-header` on a primitive input property mirrors its value into a
  `Mcp-Param-{Name}` header for routing. Never use it for secrets or personal data.

## Still current from earlier revisions

- **2025-11-25**: icons on tools/resources/prompts; tool names 1–128 chars from
  `[A-Za-z0-9_.-]`; input-validation failures are tool errors (`isError: true`), not
  protocol errors; JSON Schema 2020-12 is the default dialect; invalid `Origin` gets `403`;
  URL-mode elicitation; incremental scope consent through `WWW-Authenticate`.
- **2025-06-18**: structured tool output (`outputSchema` + `structuredContent`),
  `resource_link` content, MCP server as OAuth resource server with Protected Resource
  Metadata (RFC 9728), clients must send RFC 8707 resource indicators, JSON-RPC batching
  removed, `title` fields.

## Deprecated (avoid in new designs)

Earliest removal is the first revision on or after 2027-07-28 unless noted. Registry:
https://modelcontextprotocol.io/specification/2026-07-28/deprecated

| Deprecated | Replace with |
|---|---|
| Sampling (`sampling/createMessage`, `includeContext`) | Call an LLM provider API from the server, or return data and let the host model reason. |
| Roots | Explicit tool parameters or server configuration. |
| Logging capability | stderr, structured logs, OpenTelemetry. |
| Dynamic Client Registration | Client ID Metadata Documents (CIMD). |
| HTTP+SSE transport (two-endpoint, 2024-11-05) | Streamable HTTP. Keep SSE only to reach an unmigrated server. |

## Extensions

Extensions use reverse-DNS ids, are disabled by default, and are negotiated per request
(client `clientCapabilities.extensions`, server `server/discover` `capabilities.extensions`).
Official: MCP Apps (`io.modelcontextprotocol/ui`), Tasks, OAuth Client Credentials,
Enterprise-Managed Authorization, Skills over MCP. Treat each as opt-in:

- **MCP Apps**: a tool points `_meta.ui.resourceUri` at a `ui://` resource with MIME
  `text/html;profile=mcp-app`, rendered in a sandboxed iframe. Always return meaningful text
  content so hosts without the extension still work. Read the current helper API at
  https://github.com/modelcontextprotocol/ext-apps before writing code; do not guess names.
- **Tasks**: for long-running work the server may answer `resultType: "task"` and the client
  polls `tasks/get`. Confirm SDK support for your language before designing around it.

## Migrating an existing v1 server

- TypeScript: `npx @modelcontextprotocol/codemod@latest v1-to-v2 .`, then
  `grep -rn '@mcp-codemod-error' .` and fix each marker. Needs Node ≥ 20 and zod ^4.2.
  `@modelcontextprotocol/sdk` 1.x receives only fixes during its support window.
- Python: `from mcp.server.fastmcp import FastMCP` → `from mcp.server import MCPServer`;
  `mcp.server.fastmcp.*` → `mcp.server.mcpserver.*`; `McpError` → `MCPError`;
  `ctx.fastmcp` → `ctx.mcp_server`; transport options move from the constructor to `run()`;
  lifespan now runs once at startup. If you cannot migrate yet, pin `mcp>=1.28,<2`.
- Replace push elicitation (`ctx.elicit`, `elicitInput`) with MRTR helpers; push calls fail
  on 2026-era connections.
- Replace any SSE server transport with Streamable HTTP.
